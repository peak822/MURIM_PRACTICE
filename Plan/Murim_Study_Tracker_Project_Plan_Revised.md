## 1. ที่มาและแรงบันดาลใจ (Inspiration)

การจัดการเวลาและการสร้างแรงจูงใจในการศึกษาหรือพัฒนาตนเองมักเป็นความท้าทายที่หลายคนเผชิญ ซึ่งอาจนำไปสู่ภาวะหมดไฟ (Burnout) โปรเจกต์นี้เริ่มต้นจากความสนใจส่วนตัวในการนำแนวคิด Gamification มาประยุกต์ใช้กับแอปพลิเคชันประเภท To-Do List และ Habit Tracker โดยฉีกกฎเกณฑ์เดิม ๆ ด้วยการใช้ธีม "การฝึกตน" (Murim/Cultivation) มีเพื่อเปลี่ยนการอ่านหนังสือหรือทำภารกิจในชีวิตประจำวัน ให้รู้สึกเหมือนการทะลวงจุดชีพจรและอัปเลเวลในโลกกำลังภายใน

## 2. วัตถุประสงค์ของโปรเจกต์ (Project Goals)

- เพื่อพัฒนาทักษะการเขียนโปรแกรมด้วย Flutter และ Dart ในการสร้างแอปพลิเคชันที่สามารถรันได้ทั้งบน Android และ Windows จากโค้ดเบสเดียวกัน (Cross-Platform)
- เพื่อสร้างสรรค์ผลงาน (Portfolio) ที่มีความโดดเด่นด้าน UI/UX Design ในธีม Oriental Wuxia พร้อมแอนิเมชันที่น่าสนใจ
- เพื่อเรียนรู้การจัดการสเตตัส (State Management) และการใช้งานฐานข้อมูลแบบออฟไลน์ (Local Storage) โดยไม่ต้องพึ่งพาเซิร์ฟเวอร์

> **`✏️ แก้ไข`** เพิ่มเป้าหมายการเรียนรู้ที่ขาดหายไป: ระบุ **State Management library ที่จะใช้ให้ชัดเจนตั้งแต่ต้น** (ดูข้อ 3.1) เพราะเดิมตั้งเป็นเป้าหมายไว้ในข้อนี้ แต่ไม่มีการเลือกไลบรารีที่ชัดเจนในส่วนอื่นของแผนเลย

## 3. ขอบเขตและฟีเจอร์หลัก (Scope & Core Features)

> **`✏️ แก้ไข`** แบ่งฟีเจอร์เป็น **Core** (ต้องทำให้เสร็จภายใน 4 สัปดาห์) และ **Optional/Stretch** (ทำถ้าเหลือเวลา) เพื่อลดความเสี่ยงที่งานเชิงศิลป์อย่าง Animation จะกินเวลาจนกระทบฟีเจอร์หลัก

### 3.1 Core Features (ต้องส่งมอบ)

- **ระบบจัดการภารกิจ (Sect Missions)**: ผู้ใช้สามารถเพิ่ม ลบ และบันทึกเมื่อทำภารกิจ (เช่น อ่านหนังสือ เขียนโค้ด) สำเร็จ
- **ระบบสเตตัสวรยุทธ์ (Cultivation Status)**: การทำภารกิจจะแปลงเป็นค่าประสบการณ์ (Qi) เพื่อนำไปอัปเดตสเตตัสผู้ใช้ เช่น พลังกาย, ปัญญา, วรยุทธ์
- **หน้าต่างแดชบอร์ดสไตล์ยันต์แปดทิศ (Bagua Radar Chart)**: แสดงผลสเตตัสในรูปแบบกราฟใยแมงมุม (Radar Chart) ที่ **`✏️ แก้ไข` อัปเดตทันทีเมื่อ state เปลี่ยน (Reactive UI)** — *(เดิมใช้คำว่า "Real-time" ซึ่งคลาดเคลื่อน เพราะแอปนี้ทำงานแบบ offline เครื่องเดียว ไม่มีการรับส่งข้อมูลผ่านเครือข่าย จึงไม่ใช่ real-time ในความหมายเชิงระบบ ควรใช้คำว่า Reactive UI แทนเพื่อความถูกต้องเวลาอธิบายในพอร์ตโฟลิโอ)*
- **การทำงานแบบออฟไลน์ (Offline-first)**: ข้อมูลทั้งหมดจะถูกบันทึกไว้ในอุปกรณ์ของผู้ใช้อย่างสมบูรณ์
- **`✏️ แก้ไข` เพิ่ม — Data Model ที่ต้องออกแบบก่อนลงมือเขียนโค้ด (สัปดาห์ที่ 1)**:
  - **Mission model**: id, ชื่อภารกิจ, หมวดหมู่ (ร่างกาย/ปัญญา/วรยุทธ์), ค่า XP ที่ได้รับ, วันที่ทำสำเร็จ
  - **UserStats model**: ค่าพลังกาย/ปัญญา/วรยุทธ์, เลเวลรวม, Qi สะสม
  - **สูตรคำนวณ Qi → Stat**: ต้องระบุให้ชัดว่าภารกิจแต่ละหมวดให้ XP เท่าไหร่ และ leveling curve เป็นแบบเชิงเส้นหรือ exponential — แผนเดิมบอกแค่ "แปลงเป็นค่าประสบการณ์" โดยไม่มีสูตร ซึ่งเป็นแก่นของระบบ gamification ถ้าไม่ออกแบบก่อนจะเสียเวลาแก้ทีหลังมาก
- **`✏️ แก้ไข` เพิ่ม — State Management**: เลือกใช้ **Provider หรือ Riverpod** (เพียงพอสำหรับ scope ของโปรเจกต์เดี่ยวขนาดนี้ ไม่จำเป็นต้องใช้ Bloc ที่ซับซ้อนเกินความจำเป็น)
- **`✏️ แก้ไข` เพิ่ม — Local Storage: เลือก Hive เป็นหลักแบบเด็ดขาด** *(เดิมเขียนว่า "Hive หรือ Shared Preferences" ยังไม่ตัดสินใจ)*:
  - **Hive**: ใช้เก็บข้อมูลที่มีโครงสร้าง เช่น รายการภารกิจและสเตตัสผู้ใช้ เพราะรองรับ CRUD/query ได้ดี เหมาะกับ scope นี้มากกว่า
  - **SharedPreferences**: ใช้เฉพาะข้อมูล key-value ง่าย ๆ เช่น ธีมสี หรือการตั้งค่าเสียงเท่านั้น

### 3.2 Optional / Stretch Features (ทำถ้าเหลือเวลา)

> **`✏️ แก้ไข`** ย้ายฟีเจอร์ที่มีความเสี่ยงด้านเวลาสูงมาไว้ในหมวดนี้ เพื่อไม่ให้กระทบ Core Workflow หากทำไม่ทัน

- แอนิเมชันซับซ้อน (เอฟเฟกต์แสงเงา, แอนิเมชันรอยหมึก) — หากไม่ทันให้ใช้ transition แบบง่าย (fade/scale) ที่ Flutter มีในตัวอยู่แล้วเป็น fallback
- Responsive layout แบบเต็มรูปแบบสำหรับทุกขนาดหน้าจอ (ดูรายละเอียดในข้อ 4)

### 3.3 นอกขอบเขต (Out of Scope)

> **`✏️ แก้ไข`** เพิ่มหัวข้อนี้เพื่อป้องกัน Scope Creep ระหว่างทาง

- ระบบ Notification / Reminder
- การเชื่อมต่อฐานข้อมูลออนไลน์หรือ sync ข้ามอุปกรณ์ (วางแผนไว้เป็นแนวทางพัฒนาต่อยอดในอนาคตแทน — ดูข้อ 6)

## 6. รูปแบบการจัดทำเอกสารประกอบโปรเจกต์ (Documentation Format)

เนื่องจากเป็นโปรเจกต์ส่วนตัว การทำเอกสารจะเปลี่ยนจากรูปแบบรายงานวิชาการ 5 บท เป็นรูปแบบที่สามารถนำไปแสดงเป็น Portfolio หรือจัดทำหน้า README.md บน GitHub ได้อย่างเป็นมืออาชีพ โดยมีโครงสร้างดังนี้:

- **Project Overview**: สรุปภาพรวมและจุดเด่นของแอปพลิเคชัน พร้อมแนบภาพหน้าจอ (Screenshots) ที่สวยงาม
- **Tech Stack & Packages**: รายการเทคโนโลยีและ Flutter Packages ที่ใช้งานหลัก (เช่น `fl_chart`, `hive`, `google_fonts`) — **`✏️ แก้ไข` ควรระบุ State Management library (Provider/Riverpod) ไว้ในรายการนี้ด้วย**
- **Features Showcase**: คำอธิบายฟีเจอร์หลักพร้อมภาพเคลื่อนไหว (GIF) แสดงการทำงานจริงของระบบแอนิเมชันและอัปเดตสเตตัส
- **System Architecture / Data Flow**: อธิบายรูปแบบการเก็บข้อมูลแบบออฟไลน์ และ State Management ภายในแอป
- **Lessons Learned & Future Plans**: สรุปสิ่งที่ได้เรียนรู้และข้อผิดพลาดที่พบจากโปรเจกต์นี้ รวมถึงแนวทางในการพัฒนาต่อยอด (เช่น การเชื่อมต่อฐานข้อมูลออนไลน์ในอนาคต, ระบบ backup/export ข้อมูล)
- **`✏️ แก้ไข` เพิ่ม — Asset/Font Licensing**: ระบุแหล่งที่มาและสิทธิ์การใช้งานของไอคอน ฟอนต์ หรือภาพประกอบธีมกำลังภายในที่นำมาใช้ เนื่องจากจะเผยแพร่บน GitHub สาธารณะ ควรตรวจสอบลิขสิทธิ์ก่อนใช้เสมอ

## สรุปฉบับปรับปรุง

จุดที่แก้ไขสำคัญที่สุด 3 จุด คือ **(1)** การเพิ่มขั้นตอนออกแบบ Data Model และสูตรคำนวณ Qi ก่อนลงมือเขียนโค้ดจริง **(2)** การตัดสินใจเรื่อง Local Storage (Hive) และ State Management (Provider/Riverpod) แบบเด็ดขาดตั้งแต่ต้น และ **(3)** การแยก Core ออกจาก Optional/Stretch เพื่อลดความเสี่ยงที่งานเชิงศิลป์อย่าง Animation จะทำให้ 4 สัปดาห์ไม่พอ นอกจากนี้ยังเพิ่มหัวข้อ Risk Assessment, การวางโครง Responsive ตั้งแต่สัปดาห์ที่ 2 แทนการทำตอนท้าย, และประเด็นเรื่อง Asset Licensing สำหรับพอร์ตโฟลิโอสาธารณะ
